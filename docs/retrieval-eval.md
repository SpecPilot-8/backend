# 검색(RAG) 후보 축소 측정

코드가 LLM 컨텍스트를 넘을 때 쓸 후보 축소 단계를 만들고, 정답 근거를 얼마나 남기는지 쟀다. 2026-10-26.
판정 파이프라인에는 아직 연결하지 않았다. 지금 매칭은 레포 전체 청크를 후보로 넣는다(full_context).

## 결론

- **화면 범위 안에서 로컬 임베딩(BGE-M3)으로 검색하면 상위 30개로 판정 근거의 약 90%(Spring)·94%(React)를 남긴다.**
  상위 50개면 96%·98%다. 화면 범위 평균(Spring 90개, React 56개)보다 후보가 줄어든다
- **키워드 검색(BM25)만으로는 부족하다.** 상위 30개로 66%·83%다. 기획서는 한국어, 코드는 영어 식별자라 단어가 덜 겹친다
- **BM25와 임베딩을 섞어도(RRF) 나아지지 않았다.** K ≥ 20에서 임베딩 단독보다 2~4%p 낮다. 섞는 방식(가중치)을 바꾸면 달라질 수 있다
- **화면 범위가 먼저다.** 같은 임베딩이라도 레포 전체에서 검색하면 상위 30개로 62%·74%로 떨어진다

## 방법

`python scripts/eval_retrieval.py` (LLM 호출 없음, 두 레포 약 1분. 임베딩은 `output/embeddings/`에 캐시)

- 질의: 요구사항 본문 + 분해한 조건 문장. 청크: 파일 경로·심볼 이름 + 코드 본문 (`matcher/retrieve.py`)
- BM25: 영문 식별자는 camelCase로 나누고, 숫자는 그대로, 한글은 2-gram (PDF 추출에서 띄어쓰기가 사라짐)
- 임베딩: `BAAI/bge-m3`, 로컬 실행 (코드가 외부로 나가지 않음). 최대 4096토큰이라 긴 컴포넌트 청크도 잘리지 않는다
- 정답 근거
  - 판정 근거: 최근 전체 판정(Spring 13, React 14)에서 판정 LLM이 고른 primary 근거
  - 매칭 근거: 매칭 LLM이 레포 전체에서 고른 근거(다른 화면 코드 포함)
- Recall@K = 요구사항별 (정답 ∩ 상위 K) / 정답의 평균. 근거가 없는 요구사항은 뺀다

## 결과 (판정 근거 Recall@K)

| K | 범위 BM25 | 범위 임베딩 | 범위 혼합 | 전체 임베딩 |
|---|---|---|---|---|
| Spring 10 | 53.2% | 61.1% | 59.9% | 38.2% |
| Spring 20 | 60.9% | 82.2% | 78.4% | 54.8% |
| Spring 30 | 65.6% | **89.7%** | 86.9% | 62.4% |
| Spring 50 | 77.5% | **95.6%** | 94.7% | 75.4% |
| React 10 | 61.3% | 66.0% | 67.5% | 46.9% |
| React 20 | 72.9% | 85.2% | 81.5% | 68.0% |
| React 30 | 83.3% | **94.1%** | 90.6% | 74.4% |
| React 50 | 92.3% | **98.2%** | 97.8% | 86.9% |

화면 범위 전체를 넣으면 판정 근거는 100%(판정이 이 화면 근거에서만 고르므로), 매칭 근거는 Spring 84.9%·React 89.6%다.
매칭 근거 중 빠지는 것은 대부분 다른 화면 코드로, 화면 범위가 일부러 빼는 것이다. 매칭 근거 기준 전체 표는 스크립트 출력에 있다.

## 한계

- **정답이 LLM이 고른 근거다.** 판정 근거는 전체 코드를 본 매칭 결과에서 출발했다. 사람이 고른 근거가 아니다
- **샘플이 작다.** 청크 304개·139개라 화면 범위 자체가 작다. 큰 코드에서 K를 얼마로 할지는 다시 재야 한다
- **검색 Recall은 판정 정확도가 아니다.** 실제로 판정에 연결해 골든셋 정확도(현재 82~84%)가 유지되는지가 최종 기준이다.
  이 단계는 판정 LLM을 다시 돌려야 해서 비용이 든다
- Contextual Retrieval(청크마다 LLM이 맥락 설명을 붙여 색인)은 비용 때문에 넣지 않았다. 지금은 파일 경로·심볼 이름만 붙인다

## 다음

1. 판정 파이프라인에 연결: 화면 범위 → 요구사항별 상위 K(30~50) → 기존 선택·판정. 골든셋으로 정확도 비교
2. 로컬 LLM 전환 때 기본값으로 검토. 컨텍스트가 짧은 모델에서는 화면 범위도 다 안 들어갈 수 있다
3. 혼합 가중치, 리랭커는 상위 K에 정답이 자주 빠질 때 다시 본다

설치: 임베딩은 선택 기능이다. `pip install sentence-transformers` (torch 포함, 모델 약 2.2GB는 첫 실행 때 받음).
없으면 `--no-dense`로 BM25만 잰다.
