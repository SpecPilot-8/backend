# 웹 코드 검증 실행 연결과 실제 모델 점검

점검일: 2026-10-26. 이 문서는 `feat/web-verification-runner`의 변경과 로컬 통합 브랜치의 점검 결과다. main 병합 완료를 뜻하지 않는다.

## 기존 차단의 원인과 변경

`POST /verification-runs`는 `implementation_judgment`와 `call_flow`가 항상 누락된 것으로 기록했다. 기존 CLI는 숫자 청크 ID·명시적인 화면 진입 파일·별도 파이프라인 실행을 전제로 했으므로, v2 UUID 스냅샷과 승인된 요구사항을 HTTP 요청에서 이어 주는 실행기가 없었다. 키 입력만으로 해결되는 문제가 아니었다.

이제 준비 API → 사용자가 확인한 화면 진입 파일 → 기존 selector → 파서의 정적 화면 범위/그래프 → 기존 pre_judge/judge → ingest_verdict → 추적표·상세·통계 순서로 연결한다. 키워드 일치만으로 구현 판정을 만들지 않는다.

## 실행 계약

1. 서버 모델의 실제 연결 확인, 코드 인덱싱, 요구사항 검토 확정을 먼저 한다.
2. `POST /projects/{p}/verification-runs/prepare`에 snapshot_id, requirement_versions, model_config_version을 보낸다. 이 요청은 모델을 호출하지 않는다.
3. 화면별 `entries`의 파일을 확인한 뒤 `scope_config={stack, entries, confirmed:true}`를 같은 실행 입력에 추가해 `POST /verification-runs`를 호출한다. 지원 stack은 spring/react다. 예제 매핑은 추천일 뿐 자동 승인하지 않는다.
4. 202 Job의 queued/running/completed/failed와 중간 진행을 조회한다. 웹은 새로 열어도 진행 중 Job을 조회한다. 서버 재시작으로 중단된 작업은 failed로 남기며 유료 호출을 자동 재시도하지 않는다.
5. 결과에는 고정된 요구사항 개정·스냅샷·모델 설정·프롬프트/규칙 버전과 서버가 조인한 코드 경로·줄 번호가 들어간다. target으로 후보를 미리 거르지 않는다.

잘못된 후보 ID/조건 키, 다른 화면의 주 근거, 근거 없는 긍정 판정은 그대로 채택하지 않는다. 유효한 화면 근거와 함께 반환된 범위 밖 추가 후보는 경고로 제외한다. LLM이 도달 범위나 코드 위치를 생성하지 않는다. 소스는 실행하지 않는다.

## 실제 호출 표본

입력은 제공된 기획서의 공지사항 등록 취소 화면 1쪽에서 실제 추출한 Description 0 요구사항 1개/조건 1개다. 전체 기획서나 240개 조건의 정확도 평가는 아니다. Anthropic 서버 설정 모델을 사용했고, 이 코드 검증 점검에서 총 5회 호출했다(React 최초 매칭 1회, 보완 후 React 매칭/판정 2회, Spring 매칭/판정 2회). 자동 재시도는 하지 않았다.

| 코드 | 웹 실행 결과 | 실제 근거 | 사람 확인 |
|---|---|---|---|
| React | completed / not_found | NoticeFormPage.jsx 46–231줄, 근거 1곳 | 취소는 Link로 즉시 이동하며 작성 내용 확인 팝업이 없다 |
| Spring | completed / not_found | notice/form.html 26–83줄과 notice-form.js 등, 2개 파일·근거 6곳 | 취소는 /notices 링크이며 확인 팝업 처리가 없다 |

최초 React 실행은 유효한 주 근거와 범위 밖 추가 후보를 함께 반환해 needs_review였다. 이 재현으로 후보 ID를 스키마 enum으로 제한하고, 유효 근거와 추가 후보를 구분하는 처리를 추가했다. 프롬프트/규칙 버전을 함께 변경했다. 이후 같은 표본에서 근거가 있는 판정이 저장됐다. 이는 동일 버전의 반복 정확도 실험이 아니다.

브라우저에서 실행 진행 → 완료 → 추적표/집계 → 상세 PDF 및 코드 근거를 확인했다. 코드 근거 1/2/6개, 펼침/접기·그래프 선택·긴 코드의 내부 가로 스크롤을 확인했다. 별도의 명시적 UI 시험 데이터로 편집/저장/Excel을 점검했으며 이 데이터를 실제 모델 정확도 근거로 사용하지 않았다.

실제 수행 O/X는 사람이 수행해 저장한 기록이다. 코드 판정이나 모델의 예상값으로 실제 수행 결과를 채우지 않는다.
