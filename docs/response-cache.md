# 웹 코드 검증의 모델 응답 재사용

웹 코드 검증(`api/v2/verification_runner.py`)은 매칭·판정 호출마다 입력 전체의 해시를 키로 응답을 프로젝트 안에
저장하고(`llm_response_cache` 리소스), 같은 키가 다시 나오면 모델을 부르지 않고 저장된 응답을 쓴다.
분석 파이프라인(`scripts/run_verdict.py`)의 `input_hash` 재사용을 웹에 옮긴 것이다.

## 키

모델 이름, 사고량(effort), 지시문(프롬프트 버전 포함), 근거 코드 블록(context), 요구사항·후보 블록(prompt),
출력 스키마(후보 id enum 포함)를 모두 담은 SHA-256이다. 이 중 하나라도 바뀌면 다시 부른다.
형식 검증을 통과한 응답만 저장하고, 재사용한 응답도 같은 형식 검증과 저장 규칙을 다시 거친다.
캐시는 프로젝트별이고, 프로젝트를 지우면 함께 지워진다.

## 언제 재사용되나

| 상황 | 매칭 | 판정 |
|---|---|---|
| 같은 스냅샷·요구사항으로 다시 검증 (취소·실패 후 재시도 포함) | 전부 재사용 | 전부 재사용 |
| 일부 요구사항만 수정 | 그 화면만 다시 | 그 요구사항(과 근거가 바뀐 같은 화면 요구사항)만 다시 |
| 코드 수정 | 전부 다시 (매칭은 모든 화면이 레포 전체 목록을 받음) | 근거 코드와 매칭 결과가 그대로인 요구사항은 재사용 |
| 모델·사고량 변경 | 전부 다시 | 전부 다시 |

- 같은 입력이면 이전 판정을 그대로 쓰므로, 같은 입력의 판정 흔들림을 재려면 `SPECPILOT_DISABLE_RESPONSE_CACHE=1`로 끈다.
- 재사용한 호출 수는 단계별 `analysis_metrics.<stage>.reused_calls`에 남고, 토큰·시간 집계(`calls`, `usage`)에는 들어가지 않는다.
- 코드를 고치면 매칭 입력(레포 전체 목록)이 바뀌어 매칭은 모두 다시 부른다. 매칭이 같은 근거를 고르면 판정은 재사용되지만,
  매칭 결과가 흔들리면 판정도 다시 부른다. 변경 파일만 다시 매칭하는 것은 화면별 후보(검색 방식) 연결 이후의 과제다.

## 효과

- 바뀐 것이 없는 재검증: 모델 호출 0회 (테스트 `test_unchanged_rerun_reuses_saved_model_responses`).
- 씽크트리 Spring 샘플 전체 검증이 약 $3.4(판정 13 기준, docs/golden-score.md)이므로 같은 입력의 재검증·재시도 비용이 그만큼 사라진다.
  실제 웹 재검증 비용은 아직 실측하지 않았다.


## 시험 생성에도 적용 (2026-11-18)

시험 생성(`api/v2/test_generation_runner.py`)도 배치마다 같은 `ResponseCache`를 쓴다. 키는 검증과 같이 모델·사고량·지시문·
프롬프트·스키마 전체다. 형식 검증과 중복 정리를 통과한 응답만 저장한다. 작업 결과에 `calls`(실제 호출)와 `reused_calls`(재사용)를 남긴다.

큰 소주제를 배치로 나누면서(PR 124) 중간 배치에서 실패하면 처음부터 다시 과금되던 문제를 줄이는 것이 목적이다.
다시 생성하면 이미 끝난 배치는 호출하지 않는다.

배치 상한도 요구사항 6개·조건 15개에서 10개·25개로 올렸다. 조건 15개 배치의 출력이 평균 약 8천 토큰이라 max_tokens 32000 안에 여유가 있다.
생성 준비 응답의 `max_model_calls`는 소주제 수가 아니라 배치 수로 계산한다.

Spring '공지사항수정'(요구사항 17개, 조건 43개) 실측:

| | 호출 | 시간 | 출력 토큰 | 비용 | 시험·단계 | 품질 점검 | 관점 작성/검토 필요/미포함 |
|---|---|---|---|---|---|---|---|
| 배치 15 (PR 124) | 4 | 5분 53초 | 31,760 | $0.93 | 25 / 61 | 문구 창작 1 | 48 / 11 / 1 |
| 배치 25 | 2 | 3분 56초 | 22,555 | $0.67 (-28%) | 19 / 54 | 문제 없음 | 54 / 6 / 0 |
| 배치 25, 같은 입력 재생성 | 0 (재사용 2) | 1초 미만 | 0 | $0 | 19 / 54 | 문제 없음 | 54 / 6 / 0 |

- 두 경우 모두 조건 43개가 전부 시험에 연결됐고 경계값 누락·중복은 없었다.
- 배치를 크게 하니 지시문 반복과 배치마다 다시 만드는 공통 준비 시험이 줄어 출력이 29% 줄었다. 시험 수가 준 것도 같은 이유로 보인다.
- 1회씩 측정이라 품질 차이는 흔들림일 수 있다. 다른 소주제와 반복 실행으로 확인하지 않았다.
