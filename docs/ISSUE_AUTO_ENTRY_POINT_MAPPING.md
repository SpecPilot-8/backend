# [SPEC-ISSUE-072] AI 기반 화면 진입점 및 연관 코드 자동 매핑 (진입 파일 수동 선택 다이얼로그 제거)

## 1. 개요 (Context & Problem)
- **현재 상황**:
  - 요구사항 검토 확정 후 `[코드 검증 시작]`을 클릭하면 `VerificationScopeDialog`가 모달로 나타나, 사용자가 화면별로 어떤 소스 파일이 진입점인지 다중 선택(⌘/Ctrl 클릭)해야 함.
  - 샘플 프로젝트(`spring-sample`, `react-sample`) 외에 다른 프로젝트를 분석할 경우 추천 파일이 비어있어, 사용자가 수백 개의 소스 파일 중 엔트리포인트를 직접 찾아서 지정하지 않으면 `SCREEN_ENTRY_REQUIRED` / `SCREEN_ENTRY_INVALID` 오류로 검증이 차단됨.
- **문제점**:
  - AI 자동 검증 도구에서 "어떤 코드가 이 화면과 연관되어 있는지"를 사용자가 일일이 수동 지정하는 것은 비합리적이며 심각한 UX 저하를 유발함.
  - 기획자, 테스터뿐 아니라 개발자도 대규모 코드베이스의 엔트리포인트를 기억해 매핑하기 어려움.

## 2. 해결 목표 (Goals)
1. **원클릭 자동 검증 (Zero-Friction UX)**:
   - 사용자가 `[코드 검증 시작]` 버튼을 누르면 복잡한 수동 파일 선택 팝업 없이 **즉시 AI 검증 작업이 실행**되도록 전환.
   - 지난 작업에서 구현된 `VerificationLoadingModal`의 `Step 01 화면 도달 범위 분석` 단계에서 AI/시스템이 연관 진입점을 자동 판별하고 있음을 시각적으로 안내.
2. **지능형 진입점 자동 추론 (Auto-Scoping Engine)**:
   - 백엔드 `scope_options`: 샘플 JSON 프리셋이 없더라도 화면명/소주제/수락조건 키워드와 파일명, 경로, 컴포넌트명 간의 유사도 매칭을 통해 최적의 진입 파일을 자동 추천(추론).
   - 대표 진입 파일(Router, Controller, Main View 등)을 Fallback으로 보장하여 빈 매핑으로 인한 검증 차단 원천 방지.
3. **하위 호환성 및 유연성 보장**:
   - 기존 백엔드 API 계약(`POST /verification-runs/prepare`, `POST /verification-runs`)의 안정성을 유지하면서, 수동 커스텀이 필요한 경우를 위한 고급 설정 옵션 유지.
