# LLM 호출을 제외한 MVP 통합 점검

점검: 2026-10-24~25. 외부 LLM 호출·키 등록·모델의 정확도 평가는 제외했다.
기존 CLI 코드와 v2 웹 API는 같은 구현 상태가 아니다. 팀원 PR #54/#55의 추출·판정·시험 생성 어댑터와 생성기 소스를 보존해 검증했다.

브라우저의 수행값은 **저장 경로 검증을 위해 입력한 통합시험용 데이터**다. 검증 대상 서비스가 실제로 해당 시험을 통과했다는 의미가 아니다. PDF 블록/표 개수 역시 추출 정확도·재현율 측정값이 아니다.

## 보완한 부분

- v2 parse에 기존 화면 헤더·Description/Action 파서를 연결하고 출처 좌표·번호·문자를 보존했다. 문서 재조회는 기존 block_id를 유지한다.
- OCR 엔진/언어가 없거나 시간 초과가 나도 읽을 수 있는 다른 원문을 버리지 않는다. OCR 고신뢰도에서도 오독이 있어 원문 검토 경고를 유지한다.
- 사용자 분류 등록과 AI와 독립적인 수동 사양서 생성 API를 추가했다. AI 성공이나 가짜 판정을 만들지 않는다.
- 프런트 버전·서버 ID·스냅샷·개정 연결, 전체 페이지네이션, 6종 판정/미분석 구분, 조건 편집·원자 저장·실제 결과 분리를 수정했다.
- 임시 AI 강제 통과와 서버에 없는 프로젝트 삭제 버튼을 제거했다. 미지원 원격 Git 입력을 비활성화했다.
- 저장된 파이프라인 판정을 가져올 때 원래 코드 스냅샷과 현재 코드가 다르면 중단한다. 가져오기에서 OCR 경고를 지우지 않는다.

## 파서와 모델의 남은 한계

1. PDF 파서는 제공된 화면설계서의 헤더/오른쪽 표 구조에 맞춰져 있다. 임의 레이아웃·복잡한 표·전체 스캔 페이지·PPTX/DOCX/XLSX를 완성된 지원으로 표시할 수 없다.
2. 한국어 OCR은 Tesseract와 `kor`/`eng` 언어 데이터가 필요하다. 현재 OS 기본 언어에는 kor가 없어 테스트용 언어 데이터를 별도 폴더에 준비했다. 고신뢰도 한글 오독은 자동 교정하지 않는다.
3. 빈 표 화면 변형의 의미와 팝업 관계는 원문 검토/추출 어댑터에서 다룬다. 기본 parse는 요구사항 조건이나 관계를 추측해 만들지 않는다.
4. TypeScript/TSX는 원문 청크만 지원한다. 호출 그래프·화면 도달 범위·동적 경로·별칭 처리와 파서 오류 진단은 후속 검증이 필요하다.
5. 추출/판정/시험 생성 소스와 JSON 어댑터는 있다. 그러나 사용자용 자동 API는 여전히 blocked이며 CLI 로더를 API 워커 연결 완료로 보지 않는다.
6. 이 환경에서 PostgreSQL `specpilot` 소켓이 없어 기존 저장 판정/시험 전체 재생은 수행하지 못했다. DB 덤프 또는 비밀값을 제외한 교환 JSON·원본 스냅샷을 인계받아야 한다. 새 LLM 호출로 대체하지 않았다.
7. 키 저장·프로젝트 모델 설정·실제 연결 검사는 여전히 501이다. 이 점검에서는 구현·호출하지 않았다.
8. 운영 인증/권한, 장시간 작업 워커·재시작/재시도·진행 복원은 별도 미완료 이슈로 유지한다.

## 재현

```bash
pip install -r requirements-dev.txt
python -m pytest -q
python -m ruff check api services tests
```

브라우저: 프런트 VITE_API_URL과 백엔드 CORS를 같은 개발 환경에 맞춘다. 기본 포트는 5173/8000이며 이 점검에서는 기존 개발 데이터와 분리된 5180/18000 및 임시 SQLite를 사용했다.

수동 경로: 프로젝트·PDF/ZIP 등록 → 명세 화면 문서 파싱 → 원문 블록 선택 → 요구사항 수동 추가 → 주제/소주제/조건 입력·검토 확정 → 코드 검증 접수(blocked) → 테스트 화면 수동 사양서 생성 → 시험 추가 → 연필 편집 → 저장/취소 → Excel 출력.

선정 모델의 키를 입력하기 전에도 위 경로를 실행할 수 있다. 자동 결과가 필요한 검증은 후속 모델·워커 연결 이후 별도로 수행한다.
